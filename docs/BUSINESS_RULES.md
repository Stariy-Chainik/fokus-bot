# Каталог бизнес-правил fokus-bot

Человекочитаемая спецификация домена, извлечённая из кода по ходу рефакторинга.
Формат: **правило** — где реализовано (`file:line`) — пояснение. Это описание **текущего** поведения (эталон для тестов), а не пожелания.

## Роли и доступ
- **Три роли:** admin, teacher, client (родитель). Определяются по `User.is_admin` и `User.teacher_id` — [bot/models/entities.py:6-11](../bot/models/entities.py#L11). Пользователь загружается по `tg_id` в `AuthMiddleware`.
- **Спецроль «Клецова» (TCH-0002):** ассистент, может записывать занятия за Никишина (TCH-0005) и Криворчук (TCH-0008) через прокси; прокси требует одобрения админа — [bot/staff.py](../bot/staff.py) (`PROXY_BUTTONS`).
- **Спецроль «Контарева» (TCH-0009):** педагог с доступом к выставлению счетов, но **только по своим группам** — [bot/staff.py](../bot/staff.py) (`BILLING_TEACHERS`).

## Зарплата педагога
- **`earned = round(rate × duration_min / 45)`**, количество учеников не влияет — [bot/services/billing_service.py:10-13](../bot/services/billing_service.py#L10).
  - `rate = rate_group` для группового занятия, `rate = rate_for_teacher` для индивидуального.
- Единица нормирования — **45 минут** (`MINUTES_PER_UNIT` в [bot/utils/constants.py](../bot/utils/constants.py)).

## Счёт ученика (сумма к оплате)
- **Индивидуальное занятие:** `base = round(rate_for_student × duration_min / 45)`, делится **поровну** между участниками (слоты student_1..4), **целый остаток достаётся первому** ученику — [billing_service.py:53-70](../bot/services/billing_service.py#L53). Для пары сумма двух строк точно равна полной стоимости.
- **Групповое занятие PER_VISIT:** сумма — снапшот в `attendees` (`STU-001:60:700`); биллится каждый ученик с `amount > 0` — [billing_service.py:43-51](../bot/services/billing_service.py#L43).
- **`amount = 0` у ученика в группе = абонемент** (не биллится, не «пробное») — [attendees.py:21](../bot/utils/attendees.py#L21).
- Виртуальные billing-строки **не хранятся** — считаются on-demand из Lesson + Teacher.

## Режимы биллинга групп
- `NONE` — бесплатно, посещаемость не тарифицируется, групповое занятие сохраняется с `attendees=None`.
- `PER_VISIT` — каждое посещение по цене группы (`price_full` / `price_short`).
- `SUBSCRIPTION` — **не реализовано** — [bot/models/enums.py:20-23](../bot/models/enums.py#L20).
- **PER_VISIT группы:** GRP-0007, GRP-0008, GRP-0010, GRP-0015, GRP-0017, GRP-0018; остальные — NONE.

## Тарифы SHORT/FULL
- Деление `price_short`(dur 35) / `price_full`(dur 60) — только детсадовские группы ЮБ/БП; у остальных одна цена — [entities.py:52-64](../bot/models/entities.py#L60), `StudentGroupTier` [enums.py:26-28](../bot/models/enums.py#L26).

## Сдача периода (блокировка)
- Педагог сдаёт период (разрешено с **25-го числа месяца**); после сдачи **не может** редактировать/удалять свои занятия в этом периоде.
- Строка `TeacherPeriodSubmission` используется как **замо́к**.
- **Админ (и вызовы с `bypass_period_lock=True`) обходят блокировку** — могут создавать и удалять занятия в сданном периоде. Переоткрытие = удаление строки submission.

## Счета и оплаты
- Инвойс = `StudentPeriodPayment`, **один на `(student, teacher, period)`**; статусы `PENDING` / `PAID` — [entities.py:149-163](../bot/models/entities.py#L149).
- `get_or_create_invoices_for_student_period`: при изменившейся сумме обновляет **только не-PAID** счёт — [payment_service.py:69-77](../bot/services/payment_service.py#L69).
- `confirm_period` переводит все PENDING периода в PAID — [payment_service.py:148-159](../bot/services/payment_service.py#L148).
- **Занятие, добавленное после оплаты периода, автоматически не доначисляется** (confirm_period пропускает PAID) — задокументированное ограничение.
- **Оплата занятия ✅ вычисляется на лету:** `(date[:7], teacher_id)` есть в payments со статусом PAID. У занятий нет поля оплаты.
- **Счёт админа/биллинг-педагога обходит проверку сдачи периода** — выставить можно в любой момент, сумма пересчитывается из текущих занятий.
- Фискальный чек (CloudKassir) отправляется при подтверждении оплаты, если сервис настроен и у клиента есть телефон.
- Способы оплаты (наличные / реквизиты / СБП / ЮКасса) видны только если сконфигурированы через ENV.
- **Webhook ЮКассы верифицируется:** телу запроса не доверяем — из него берётся только `object.id`,
  платёж перепроверяется через API ЮКассы; подтверждение только при реальном `succeeded` —
  [bot/handlers/client/payments.py](../bot/handlers/client/payments.py) (`process_yookassa_event`).
  `PAID` ставится ровно двумя путями: верифицированный webhook или подтверждение админа.
- **Долг ученика** (экран «⚠️ Должники») = начисления по всем занятиям минус PAID-оплаты по
  `(student, teacher, period)`; выставлялся ли счёт — не важно; `amount=0` (абонемент) в долг
  не входит — [payment_service.py](../bot/services/payment_service.py) (`compute_debt_map`).
  Текущий (незакрытый) месяц показывается админу с пометкой, но в напоминания родителям
  **не включается** — напоминаем только за закрытые месяцы (правило месячного закрытия).

## Видимость педагог ↔ ученик
- Педагог видит ученика ⇔ пересечение `teacher_groups ∩ student_groups` непусто — [bot/services/visibility.py:9-15](../bot/services/visibility.py#L9). Таблицы `teacher_students` **нет**.
- Ученик может состоять в нескольких группах; биллинг агрегирует по всем за период.
- Одну группу могут вести несколько педагогов; занятие принадлежит `lesson.teacher_id`.

## Занятия
- **Денормализация имён:** `lesson.teacher_name`, `student_N_name` — снапшоты на момент создания; переименования историю не переписывают — [entities.py:80-103](../bot/models/entities.py#L80).
- **Гард дублей:** соло (ровно 1 ученик) блокируется по `teacher + student + date` (`individual_lesson_exists`); групповые **не** блокируются (разные смены в один день); пары не блокируются.
- INDIVIDUAL занятие может содержать 1–4 учеников (разовые микрогруппы из солистов) — [entities.py:98-103](../bot/models/entities.py#L98).

## Клиент vs Ученик
- Ученик занимается, клиент (родитель) платит — разные сущности: `student.client_id → Client`, `student.parent_tg_ids → list[int]` (доступ в бот).
- **Разделитель `parent_tg_ids` — `|`, не `,`** (RU-локаль Google Sheets портит числа через запятую). Парсер принимает и `,` для обратной совместимости.
- **Регистрация клиента:** первый ученик — напрямую; добавление второго требует одобрения админа (`client:add_child`).

## Идентификаторы
- Последовательные строковые ID: `TCH-/STU-/LES-/PAY-/SUB-/BRN-/GRP-/USR-/CLT-`; генератор берёт максимум среди существующих, игнорируя некорректные — [bot/utils/ids.py:8-19](../bot/utils/ids.py#L8).
