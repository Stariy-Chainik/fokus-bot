**Реализовано 2026-07-10** (ранее было отложено «после клиент-роли»). Модель, выбранная пользователем:

- `GroupBillingMode.SUBSCRIPTION` — **фиксированная `price_full` ₽/месяц с каждого ученика группы,
  количество занятий НЕ влияет** (не «N занятий за блок со списанием», как планировалось раньше).
- Начисляется за месяц, где у группы было ≥1 занятие (каникулы — не платят); посещал ли конкретный
  ученик — не важно; посещаемость не отмечается (attendees=None, как NONE).
- Ключ начисления в счетах/долгах — синтетический `SUB:{group_id}` в поле teacher_id инвойса
  (`PaymentService._subscription_bills_for_student`).
- Включается: карточка группы → «Биллинг ученикам» → «💳 Включить абонемент (₽/мес)».

**Why:** пользователь сформулировал правило «группы по абонементу оплачиваются один раз в месяц
независимо от количества занятий» и подтвердил 4 решения (начисление при наличии занятий; одна цена
= price_full; без отметки посещаемости; в боте сейчас).

**How to apply:** `amount=0` в attendees PER_VISIT-группы по-прежнему означает «абонементщик в
per-visit группе» ([[attendee_amount_zero]]); полноценный абонемент группы — это режим SUBSCRIPTION.
«Выручка» учитывает абонементы (блок «💳 Абонементы», разбивка по группам, месячный вид) — сделано 2026-07-10.

**Дополнение 2026-07-10:** цена абонемента переопределяется на конкретный месяц — для одного
ученика или всей группы (лист `subscription_overrides`, `SubscriptionOverrideRepository`).
Приоритет: ученик → группа → price_full; `0` = не начислять в этом месяце. UI — «Биллинг
ученикам» группы (`subovr:*`).

**Смена базовой цены — только вперёд** (правило пользователя): при изменении цены админ
указывает месяц начала действия; прошлые месяцы с занятиями автоматически фиксируются
старой ценой (или 0 при первом включении) — `pin_subscription_history`. Менять цену в
середине сезона безопасно.
