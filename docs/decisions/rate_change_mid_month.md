Цены у педагога меняются не только с начала месяца. Пример: Контарева (TCH-0009) —
повышение для клиента **с 4 сентября 2026**, занятия 1–3 сентября считаются по старой
цене (1125 / 1300 / 1900). Реализовано 20.09.2026: в листе `teacher_rate_history`
граница `until_period` может быть днём `YYYY-MM-DD`, а не только месяцем `YYYY-MM`;
`rate_history.effective_rates(teacher, when)` принимает дату занятия, и все денежные
места (`calc_earned`, `build_billing_rows`, `SalaryService`, «Прибыль», API кабинетов)
передают `lesson.date`, а не `lesson.date[:7]`.

**Why:** до этого ставка бралась на месяц целиком, поэтому занятия начала месяца
пересчитывались по новой цене — у родителей появлялся «долг», которого не было.
**How to apply:** новое повышение в середине месяца → строка в `teacher_rate_history`
со старыми ставками и границей «последний день по старой цене». Месячные строки
продолжают работать как раньше (см. [[payment-invariant]]).
