**Инвариант оплат (правило пользователя, 2026-07-10):** количество оплаченных клиентом занятий
должно быть **не меньше** количества отмеченных педагогом. Касается индивидуальных И групповых.

**Механизм с 2026-09-11 — накопительный счёт** (`PaymentService.ledger_for`,
`bot/services/payment_ledger.py`): по связке (ученик, педагог, месяц) оплаты складываются, остаток
«начислено − оплачено» доначисляется автоматически новой строкой-остатком; занятия, отмеченные после
оплаты, попадают в «к доплате», «Должники» и напоминания. Родитель видит ✅/⬜ на каждом уроке
(галочки по порядку дат) и «Не оплачено: N ₽» в «Занятиях». Сдача периода по-прежнему запирает
добавление занятий педагогом. Решение владельца: трём родителям, оплатившим занятие Никишина 04.09
по 700 до повышения, снимок оставлен 700 (доплата 100 не начисляется).

**Why:** пользователь явно зафиксировал это как ключевую гарантию биллинга; кейс Осиповой (сентябрь
2026: оплачено 18 366 при начислении 21 766) показал, что без доначисления оплата «после каждого
урока» не поддерживается.

**How to apply:** новые экраны/флоу оплат считать через `ledger_for` (суммы), не через булев статус
строки; оплаченные строки никогда не менять; переплата после удаления урока показывается, но не
переносится автоматически.
