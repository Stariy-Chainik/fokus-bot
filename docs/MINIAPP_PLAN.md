# Telegram Mini App — план реализации

Прототип (кликабельный, без бэкенда): `web/miniapp-prototype.html` / артефакт
https://claude.ai/artifact/U9bp9iTbfTpTm6WL9cBMmx. Реализация идёт по нему, кабинет за кабинетом:
**администратор → педагог → спортсмен → родитель**. Родители потом получают ту же страницу
и в MAX (мини-приложение MAX); админ, педагоги и спортсмены — только Telegram.

## Архитектура

- **Фронт** — `miniapp/` (`index.html`, `app.js`): один файл на кабинет, без сборки и Node на
  сервере. Раздаётся тем же aiohttp-сервером бота по `/app/` (`bot/api/static.py`).
  Подключён `telegram-web-app.js`: `ready/expand`, кнопка «Назад» (`BackButton`), тема.
- **API** — `bot/api/admin.py`, префикс `/api/admin/*`, JSON. Тонкий слой над сервисами бота:
  суммы, остатки и отметки считает **тот же** `PaymentService`/`SalaryService`, что и Telegram-экраны,
  фронт ничего не пересчитывает. Один запрос = один экран (DTO под экран).
- **Авторизация** — заголовок `Authorization: tma <initData>`; подпись Telegram проверяется на
  каждый запрос (`bot/utils/telegram_auth.py`), затем роль из листа `users` (`is_admin`).
  Для локальной разработки без Telegram: `MINIAPP_DEV_TG_ID=<tg_id>` + заголовок `Authorization: dev`
  (фронт шлёт его при `?dev=1`). На проде переменная пустая — заголовок игнорируется.
- **Сервер** — тот же процесс, что и вебхук ЮКассы (`PAYMENT_WEBHOOK_PORT`, 8081). Для Telegram нужен
  HTTPS-домен: nginx → 127.0.0.1:8081 (`/app/`, `/api/`, `/yookassa-webhook`), сертификат Let's Encrypt,
  затем BotFather → Bot Settings → Menu Button → `https://<домен>/app/`.

## Локальная разработка

```bash
MINIAPP_DEV_TG_ID=<ваш tg_id> .venv/bin/python scripts/miniapp_dev.py --port 8090
# http://localhost:8090/app/?dev=1
```

Скрипт поднимает API + фронт **без** Telegram-поллинга (прод продолжает работать), но данные —
живая таблица из `.env`: кнопки подтверждения оплат пишут в неё по-настоящему.
Тесты API: `tests/test_admin_api.py` (aiohttp `TestClient`, фейковые репозитории, реальный `PaymentService`).

## Этапы кабинета администратора

| Этап | Экраны | API | Статус |
|---|---|---|---|
| 1 | Сводка; Оплаты: подтвердить (месяц → филиал/группа → ученик → позиции → выбор занятий → сумма и способ), абонемент целиком; Счёт ученика + отправка родителям; Должники (просмотр); Ученики (поиск, карточка со счетами по месяцам); Педагоги (список, карточка) | `GET /me`, `/home`, `/students`, `/students/{id}`, `/teachers`, `/teachers/{id}`, `/pay/groups`, `/pay/students`, `/pay/student/{id}`, `/pay/marks/{id}`, `POST /pay/confirm`, `POST /pay/confirm-invoice`, `GET /bill/{id}`, `POST /bill/{id}/send`, `GET /debtors` | ✅ |
| 2 | Должники → напомнить всем; Финансы: прибыль (месяц/день, ➕ доход/расход), зарплаты (строки), выплаты (остаток, аванс, нестандартный день); история оплат по фамилии | `/debtors/remind`, `/profit`, `/profit/day`, `/finance`, `/salaries`, `/payouts` | — |
| 3 | Филиалы и группы: CRUD, биллинг (режим, цена с месяца, переопределения), месяцы членства, состав, педагоги группы, архив; ученик: группы, партнёр, родитель, тариф, переименование, удаление; педагог: ставки с месяца, группы, открыть период, удалить, добавить | `/groups/*`, `/branches/*`, `/students/{id}/…`, `/teachers/{id}/…` | — |
| 4 | Изменить занятия (педагог → фильтр → удалить, гость); отметить за педагога (мастер записи); очередь решений (чеки, наличные, заявки) — требует хранения ожидающих запросов, сейчас они живут только в сообщениях Telegram | `/lessons/*`, `/record/*`, `/inbox/*` | — |

Дальше — кабинет педагога (`/api/teacher/*`), спортсмена, родителя (последний; родительские
экраны берутся из `bot/screens` + `parent_views`, чтобы та же страница открывалась и из MAX).

## Что нужно от владельца перед запуском в Telegram

1. Домен (любой, ~300–500 ₽/год) с A-записью на 178.104.240.252.
2. На сервере: nginx + certbot (делается один раз, ~15 минут).
3. В BotFather: кнопка меню `https://<домен>/app/`.

До этого кабинет проверяется локально (`miniapp_dev.py`).
