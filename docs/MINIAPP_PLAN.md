# Telegram Mini App — план реализации

Прототип (кликабельный, без бэкенда): `web/miniapp-prototype.html` / артефакт
https://claude.ai/artifact/U9bp9iTbfTpTm6WL9cBMmx. Реализация идёт по нему, кабинет за кабинетом:
**администратор → педагог → спортсмен → родитель**. Родители потом получают ту же страницу
и в MAX (мини-приложение MAX); админ, педагоги и спортсмены — только Telegram.

## Архитектура

- **Фронт** — `miniapp/` (`index.html`, `app.js`): один файл на кабинет, без сборки и Node на
  сервере. Раздаётся тем же aiohttp-сервером бота по `/app/` (`bot/api/static.py`).
  Подключён `telegram-web-app.js`: `ready/expand`, кнопка «Назад» (`BackButton`), тема.
- **API** — `bot/api/admin.py`, префикс `/api/admin/*`, JSON. Тонкий слой над сервисами бота:
  суммы, остатки и отметки считает **тот же** `PaymentService`/`SalaryService`, что и Telegram-экраны,
  фронт ничего не пересчитывает. Один запрос = один экран (DTO под экран).
- **Авторизация** — заголовок `Authorization: tma <initData>`; подпись Telegram проверяется на
  каждый запрос (`bot/utils/telegram_auth.py`), затем роль из листа `users` (`is_admin`).
  Для локальной разработки без Telegram: `MINIAPP_DEV_TG_ID=<tg_id>` + заголовок `Authorization: dev`
  (фронт шлёт его при `?dev=1`). На проде переменная пустая — заголовок игнорируется.
- **Сервер** — тот же процесс, что и вебхук ЮКассы (`PAYMENT_WEBHOOK_PORT`, 8081). HTTPS даёт Caddy
  на том же VPS (см. «Домен и вход» ниже); кнопка входа — в меню админа бота и кнопка меню чата.

## Локальная разработка

```bash
MINIAPP_DEV_TG_ID=<ваш tg_id> .venv/bin/python scripts/miniapp_dev.py --port 8090
# http://localhost:8090/app/?dev=1
```

Скрипт поднимает API + фронт **без** Telegram-поллинга (прод продолжает работать), но данные —
живая таблица из `.env`: кнопки подтверждения оплат пишут в неё по-настоящему.
Тесты API: `tests/test_admin_api.py` (aiohttp `TestClient`, фейковые репозитории, реальный `PaymentService`).

## Этапы кабинета администратора

| Этап | Экраны | API | Статус |
|---|---|---|---|
| 1 | Сводка; Оплаты: подтвердить (месяц → филиал/группа → ученик → позиции → выбор занятий → сумма и способ), абонемент целиком; Счёт ученика + отправка родителям; Должники (просмотр); Ученики (поиск, карточка со счетами по месяцам); Педагоги (список, карточка) | `GET /me`, `/home`, `/students`, `/students/{id}`, `/teachers`, `/teachers/{id}`, `/pay/groups`, `/pay/students`, `/pay/student/{id}`, `/pay/marks/{id}`, `POST /pay/confirm`, `POST /pay/confirm-invoice`, `GET /bill/{id}`, `POST /bill/{id}/send`, `GET /debtors` | ✅ |
| 2 | Должники → напомнить всем; Финансы: прибыль (месяц/день, ➕ доход/расход, расшифровка педагога), зарплаты (строки), выплаты (остаток, аванс, нестандартный день); история оплат по фамилии → месяцы → оплаты | `POST /debtors/remind`, `GET /profit`, `/profit/day`, `/profit/teacher/{id}` (с именами учеников занятия), `/profit/subscription/{gid}` (состав абонементной группы: начислено/оплачено), `/profit/breakdown` (выручка и прибыль: составляющие + занятия по дням), `POST /finance`, `DELETE /finance/{id}`, `GET /salaries`, `/salaries/{id}`, `GET /payouts`, `/payouts/{id}`, `POST /payouts`, `POST /salary-overrides`, `DELETE /salary-overrides/{id}`, `GET /payhist`, `/payhist/{id}`, `/payhist/{id}/{ym}` (`bot/api/admin_finance.py`) | ✅ |
| 3 | Вкладка «Школа»: филиалы и группы (создать, переименовать, удалить, архив), биллинг группы (режим, цена абонемента «с месяца» с фиксацией прошлых, переопределения ученик/группа × месяц/постоянно), состав (добавить, убрать с месяцем ухода, месяцы членства), педагоги группы; ученик: создать, переименовать, удалить, группы, партнёр, родитель (клиент из списка или новый), тариф, отвязать спортсмена; педагог: создать (с привязкой tg), ставки, группы, открыть период, удалить | `bot/api/admin_manage.py`: `/branches*`, `/groups*` (+`/billing`, `/overrides`, `/teachers`, `/members`), `/students*` (+`/partner`, `/groups`, `/tier`, `/client`, `/athlete`), `/clients`, `/teachers*` (+`/groups`, `/periods/{ym}/open`) | ✅ |
| 4 | Занятия за день с карточкой и удалением (`bot/api/admin_lessons.py`); отметить занятие за педагога — мастер как в боте (`bot/api/record.py`: дата → тип → длительность → группа/посещаемость с разовым тарифом, пары, солисты вместе/по отдельности, индивидуальные revenue-share; общий модуль для кабинета педагога). Осталось: гость в сохранённое занятие; очередь решений (чеки, наличные, заявки — требует хранения ожидающих запросов, сейчас они живут только в сообщениях Telegram) | `/lessons*`, `/record/options`, `POST /record` ✅; `/inbox/*` — | почти |

Дальше — кабинет педагога (`/api/teacher/*`), спортсмена, родителя (последний; родительские
экраны берутся из `bot/screens` + `parent_views`, чтобы та же страница открывалась и из MAX).

## Домен и вход (сделано 2026-09-18)

- Адрес: **https://fokus.178-104-240-252.sslip.io/app/** — sslip.io резолвит имя в IP сервера без
  покупки домена; HTTPS выпускает Caddy (контейнер `n8n-caddy-1`, конфиг `/opt/n8n/Caddyfile`,
  блок `fokus.…sslip.io` → `172.18.0.1:8081`, наружу открыты только `/app/*` и `/api/*`).
  Свой домен позже: A-запись на 178.104.240.252, такой же блок в Caddyfile, `MINIAPP_URL` в `.env`,
  `docker exec n8n-caddy-1 caddy reload --config /etc/caddy/Caddyfile`.
- `MINIAPP_URL` на проде задан → в меню админа бота первая кнопка «🖥 Открыть кабинет» (web_app).
- Кнопка меню «Кабинет» рядом с полем ввода — только в чатах админов: `scripts/set_miniapp_menu.py`
  (`--reset` возвращает стандартное меню). Родители и педагоги её не видят.
- Вебхук ЮКассы по-прежнему принимает по `http://IP:8081/yookassa-webhook`.
